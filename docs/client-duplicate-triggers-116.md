## Duplicate Instance

Instance Settings now offers Duplicate Instance above Done/Delete, with matching vertical and horizontal navigation. The asynchronous operation copies the instance folder, including game worlds, mods, shaders, resource packs, config/options, empty directories, installed-content receipts and queues. It preserves version, loader, icon, readiness and the one-time default-content state, assigns a new UUID and an automatically unique Copy name, then selects the result. Files have independent contents; no hard links are created. Root-level account data, shared download cache, launcher-wide preferences and existing favorites remain in their original shared locations.

The launcher performs this while gameplay is closed. It stages regular files under a private marked pending-copy journal and reports byte progress; cancellation and I/O errors clean up the unpublished copy. Symbolic links and special files are rejected. Publication moves the completed folder into instances and saves metadata; a failed metadata save removes the unpublished copy and retains the original. Startup recovery removes marked uncommitted copies, preserves committed ones and can restore a committed folder from its retained stage. Unknown/unmarked targets are not removed. Post-commit journal cleanup can be deferred. This is best-effort interruption recovery, not a durable power-loss transaction or protection against an external writer changing source files during the copy. The original instance is never moved or overwritten by duplication.

Host tests compare worlds/mods/config/Unicode pack names/receipts/queues byte for byte; verify edits to a clone leave the original unchanged; and cover progress, unique names/IDs, cancellation, metadata-write failure, link rejection, staged/committed recovery, account/cache preservation and asynchronous UI routing without network. The actual native Vulkan settings screen was rendered and visually checked with the duplicate button selected. Actual PS5 copy/open/save and storage-full behavior remain pending.

## Controlify adaptive triggers

Controlify's raw47-byte DualSense effect callback previously returned unsupported. The SDL PS5 driver now decodes enabled L2/R2 commands into the real120-byte native scePadSetTriggerEffect parameter layout after a successful native OFF probe. Both commands are validated before submission. Wire R2/L2 ordering is translated to native L2/R2 ordering, with explicit masks so changing one trigger preserves the other.

Supported Controlify effects are OFF, feedback/resistance, weapon, vibration, per-zone feedback and per-zone vibration. Controlify expresses slopes as feedback zones, which are retained. Uniform zone patterns use native feedback/vibration modes; nonuniform patterns use the native multiple-position modes. Unknown, calibration and malformed packet modes are rejected rather than forwarded as raw HID reports. Unrelated LED/microphone/audio fields are not implemented by this callback; impulse trigger rumble remains unsupported. Gyro, compatible rumble and HD actuator-audio paths remain in place.

Active trigger effects reset on joystick close, controller disconnect, pad-read failure or intercepted system input. New effects are refused while disconnected/intercepted. Reset is best effort when the native device itself fails. Logging records the probe, first successful command and native errors instead of logging every successful game update. This adds no Java/mod/game JAR transformations.

The protocol test uses the unchanged publisher-hash-verified Controlify3.5.3 JAR (Modrinth fo76vL20) to serialize actual FFM packets for OFF, feedback, weapon, vibration, multiple-position and slope cases. The actual C translator checks exact native ABI/masks/fields under ASan/UBSan, including both/partial commands and malformed inputs. Native pad fixtures cover submission and reset; target SDL/app link and package audits pass. Reference definitions: [Controlify trigger effects](https://github.com/isXander/Controlify/blob/main/src/main/java/dev/isxander/controlify/driver/dualsense/DualsenseTriggerEffect.java) and [packet layout](https://github.com/isXander/Controlify/blob/main/src/main/java/dev/isxander/controlify/driver/dualsense/DualsenseEffectsState.java). Physical trigger feel, mode availability and coexistence with haptics require PS5 testing; an OFF probe does not establish every effect on hardware.
